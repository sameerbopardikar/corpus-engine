## Registry policy recommendations

- Treat each benchmark’s **task definitions, evaluator, environment image, dataset version, and code commit** as evidence; a leaderboard row alone is only a reported claim.
- Keep upstream and independently corrected variants as separate sources, linked by `corrects` or `derived_from`.
- Separate benchmark-family versions such as OSWorld and OSWorld 2.0; do not overwrite historical methodology.
- Store papers and repositories as linked records when adapters require separate refresh cadences: paper metadata is effectively frozen, while code/data should refresh weekly or faster.
- Record contamination controls, human baselines, task validity, pass-at-*k*, retry budgets, scaffolding, model/tool costs, and grader changes before comparing scores.
- Do not promote benchmark superiority into architecture doctrine without local or independent production evidence.
