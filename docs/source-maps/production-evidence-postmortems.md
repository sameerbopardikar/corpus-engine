## Recommended registry policy

1. **Separate evidence lanes:** `architecture`, `deployment`, `reliability-eval`, `security-incident`, `operational-postmortem`, and `long-horizon`.
2. **Preserve source incentives:** first-party engineering, independent research, official vulnerability records, press releases, and vendor customer stories should not share the same authority score.
3. **Require failure detail for “postmortem”:** timeline, root cause, contributing factors, blast radius, remediation, and verification. The Replit statement is therefore an **incident statement**, not a completed postmortem.
4. **Track claims independently from sources:** metrics such as hours autonomous, tasks completed, staff-equivalent output, or accuracy should carry `claim_owner`, `measurement_method`, and `independent_corroboration`.
5. **Prefer rolling sources for corpus expansion:** METR’s dashboard, NVD/CVE updates, Anthropic Engineering, GitHub’s AI engineering feed, Cursor’s blog, and original security-research feeds have the best ongoing yield.

- Canonical URLs were checked directly; most returned HTTP 200 with matching titles. OpenAI blocked anonymous scripted retrieval with HTTP 403, but its canonical URLs were corroborated through official OpenAI announcements.
- `web_search`/`web_extract` were unavailable because the configured provider had no credits, so discovery used public X search and direct neutral-`User-Agent` URL checks.
- **Files created or modified:** none. Research was read-only.
